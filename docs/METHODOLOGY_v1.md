## 2. 입력과 부호

**방향.** 모든 방향은 은행 기준이다. `receive`는 은행이 받는 다리이고, `pay`는 은행이 내는 다리다.

**고객 거래.** 다리 두 개로 이루어진다. 각 다리의 입력 항목은 다음과 같다.
- 통화, 명목(해당 통화)
- 고정금리 또는 변동 + 스프레드
- 연 지급 횟수, 일수 계산, 만기 원금 교환 여부

**지급 일정** (`curves.schedule`, `MarketData.schedule`). 실제 날짜로 만든다.
- 시작일 = 평가일 + 결제 지연. 원화 IRS는 T+1, 나머지(통화스왑, FX 선도, 달러 OIS)는 T+2.
  영업일은 거래 통화들의 공통 달력(서울, 뉴욕 국채, 도쿄)이다.
- 만기일 = 시작일 + 만기(개월 단위로 반올림), 수정 익영업일.
- 지급일은 조정 전 만기일(시작일 + 만기)에서 `12 / 연 지급 횟수`개월씩 거꾸로 잡은 뒤 각각 수정 익영업일로 조정한다
  (QuantLib 스왑과 같은 방식). 조정한 만기일에서 거꾸로 잡으면 만기일이 휴일일 때 시작 부분에 며칠짜리 구간이 생긴다.
  FX 선도는 만기일(수정 익영업일) 한 번이다.
- 지급액은 `명목 x 금리 x 일수 비율`이다. 일수 비율은 다리의 일수 계산(ACT/365F 또는 ACT/360)으로 실제 날짜 사이를 센다.
- 시점은 평가일부터 ACT/365F로 잰 년이다. 거래 마지막 지급 시점(`end_time`)이 시뮬레이션·SA-CCR 잔존만기의 끝이다.
- **근사:** OIS 지급 지연(2영업일)은 거래 평가에 반영하지 않는다(커브 부트스트랩에는 반영). 영향은 날짜에 따라 다르다. 보통은 0.01bp 안이지만(JPY OIS 25년 0.0058bp) 지급 지연이 연말 휴일에 걸리면 단기 OIS에서 더 커진다(11-25 스냅샷 USD OIS 1개월 0.24bp, 9개월 0.09bp). 가격 영향은 1개월 이하 구간이라 무시할 수준이다.

**원금 교환.**
- 시작일 원금 교환은 현물로 결제된다고 보고 가치·익스포저에서 제외한다.
- 따라서 명목 비율이 현물환율과 다를 때 생기는 거래일 차액은 계산에 들어가지 않는다.

**헤지 거래.**
두 구조의 차이는 라인피 외에 넘어온 오프마켓 가치가 있느냐뿐이다.

| 구조 | 고객 거래 시가 (은행 기준) | 헤지 거래 시가 | 첫날 조달 |
|---|---|---|---|
| 딜러 라인 | + 라인피 현재가치 (라인피만큼만 오프마켓) | 0 (Par) | 없음 |
| BTB (공공기관 A–딜러 B 건, 2026-11-11 시장) | + 넘어온 오프마켓 + 라인피 (79.3 + 17.1 = 96.4억) | − 넘어온 오프마켓 (−79.3억, 라인피 제외) | 넘어온 오프마켓만큼 VM 지급 |

- **BTB:** 헤지는 고객 거래와 방향만 반대인 같은 조건이다. 넘어온 오프마켓을 포함하고 라인피는 제외한다.
- **딜러 라인:** 딜러와 Par로 반대 포지션만 막는다(`pricing.market_hedge`).
  - 통화스왑은 미러 거래의 은행 지급 다리 금리(변동이면 스프레드)를 조정해 거래일 가치를 0으로 만든다.
  - FX 선도는 KRW 다리 금액(선도환율)을 조정해 거래일 가치를 0으로 만든다.
  - 화면은 라인피를 넣기 전 고객 조건이 시장가와 얼마나 다른지(`pricing.market_gap`, bp 또는 원)를 보여준다.
    0.1bp(FX 선도 0.05원)를 넘으면 경고하고 "고객 조건을 시장가로" 버튼(`pricing.par_client`)을 띄운다.
- **직접 입력:** BTB 헤지의 실제 조건(예: 딜러 B 쿠폰)을 그대로 쓴다. 고객 조건과의 차이가 곧 라인피다.

**라인피 받는 방법** (`trade.build_deal`, `Trade.favoured`). upfront는 BTB 구조에만 있다.
"라인피 받는 방법"의 upfront 선택지는 BTB에만 있고, 직접 입력(BTB 헤지의 실제 조건)은 upfront 금액만 넣을 수 있다.

| 방법 | 통화스왑 | FX 선도 | 가능한 구조 | 경제적 효과 |
|---|---|---|---|---|
| 고객 다리 | 고객이 내는 다리(은행 수취) 금리·스프레드에 가산 (연 bp) | 고객 선도환율 마진 (원/외화 1단위) | 전부 | 무담보 고객 시가 증가 → CVA 자본 증가 |
| 헤지 다리 | 딜러에게 주는 다리 금리에서 차감 | 헤지 선도환율 마진 | BTB, 직접 입력 | 딜러에 낼 VM 감소, 고객 익스포저 불변 |
| upfront | 거래일 현금 | 거래일 현금 | BTB (직접 입력은 금액만) | 익스포저 불변 |

통화스왑의 연 bp는 해당 다리 명목 기준이고 그 다리의 일수 계산을 따른다.
FX 선도 마진은 KRW 다리 금액을 `마진 x 외화 명목`만큼 은행에 유리하게 바꾼다.
화면 단위는 원/외화 1단위이고 엔은 원/100엔이다(내부는 원/1엔).

**상대방 입력 항목.**
- 신용 위험가중치(표준방법)
- BA-CVA 업종·등급(위험가중치 표는 별표3 313.(2) = CRE50.16)
- 연 PD, LGD
- CSA 유형: 없음, VM, VM+IM

**은행 파라미터.**

| 항목 | 기본값 |
|---|---|
| CET1 목표비율 | 13% |
| 세후 요구수익률 | 10% |
| 세율 | 27.5% |
| FTP 스프레드 (USD 현금 담보: FTP − SOFR) | 12bp |
| FTP 스프레드 (KRW 현금 담보: FTP − CCP KRW 담보 이자, CCP 원화 IRS의 FVA) | 12bp (임시, 확인 필요) |
| KVA 조달 스프레드 alpha (r(t) = CD 커브 + alpha) | 10bp (파라미터) |

## 3. 시장 데이터 ([linefee/market.py](../linefee/market.py), [linefee/curves.py](../linefee/curves.py))

커브는 QuantLib 1.44 헬퍼에 시장 상품을 실제 관행대로 넣어 `PiecewiseLogLinearDiscount`(ACT/365F)로 부트스트랩한다.

| 커브 | 용도 | 상품 (블룸버그) | 관행 |
|---|---|---|---|
| USD SOFR | USD 할인(USD 담보) = SOFR 추정 = 자국 담보 | SOFR OIS 1주·1·2·3·6·9개월, 1년, 18개월, 2~30년 (`USOSFR1Z,A,B,C,F,I,1,1F,n`) | T+2, 연 1회(1년 미만은 만기 일시), ACT/360, 지급 지연 2일 |
| JPY TONA | TONA 추정 = 자국 담보 | TONA OIS 같은 만기 (`JYSO…`) | T+2, 연 1회, ACT/365F, 지급 지연 2일 |
| KRW CD | CD 91일 추정 = 원화 IRS 할인(자국 담보, 단일 커브) | CD 91일(`KWCDC Index`), IRS 6·9개월, 1년, 18개월, 2~30년 (`KWSWOF,I,1,1F,n`) | T+1, 고정·변동 분기, ACT/365F, 서울 |
| KRW (USD 담보) | KRW 할인 | 1년 이하: USDKRW 온쇼어 스왑포인트 1주~12개월(`KRW{n}M` = `KWO{n}M`, 블룸버그 증권 유형 "ONSHORE FORWARD". NDF는 `KWN`). 2년 이후: KRW 고정 vs SOFR CCS(`KRWNSQ{n}`) | 포인트: 현물(T+2)부터, 원 단위. CCS: KRW 분기 ACT/365F vs SOFR 복리 분기 ACT/360, 원금 교환, 서울·뉴욕 |
| JPY (USD 담보) | JPY 할인 | 1년 이하: USDJPY 스왑포인트(`JPY{n}M`, /100). 2년 이후: TONA + 베이시스 vs SOFR(`JYBSS{n}Y`) | 분기 복리, 원금 교환, 도쿄·뉴욕 |
| 현물 | | USDKRW, USDJPY (JPYKRW는 교차 환율로 계산해 커브와 일관되게) | 현물 결제일 T+2 |
| 환율 변동성 | | ATM 내재, 1·3·5·7·10년 (`USDKRWV{n}Y`, `JPYKRWV{n}Y`, `USDJPYV{n}Y`) | |
| 과거 추정 | | 5년 금요일 주간 변화. 금리 10년(정규), 환율 로그. KRW IRS 10년은 변동성만 | `USOSFR10`, `KRWNSQ10`, `JYSO10`+`JYBSS10Y`, `KWSWO10` |

KRW CCS(`KRWNSQ`, 블룸버그 명칭 "KRWUSD ON CCS (SOFR)")의 일수 계산 ACT/365와 T+2 결제는 블룸버그 필드
(`DAY_CNT_DES`, `SETTLE_DT`)로, KRW 다리 분기 지급은 사용자 확인(2026-11-12)으로 확정했다.
SOFR 다리 지급 지연 0은 시장 관행에 따른 가정이다.

**커브 구축.**
- 넘파이 엔진은 부트스트랩된 커브의 노드(시점, 할인계수)를 꺼내 같은 보간(로그 할인계수 선형)을 쓴다(`curves.Curve`).
  노드 사이 값은 QuantLib과 같다. 30년 뒤는 마지막 구간 선도금리로 연장한다(화면 만기는 30년까지).
- USD 담보 KRW·JPY 커브는 USD SOFR 커브를 담보 커브로, SOFR·TONA 지수를 각자의 추정 커브로 둔 교차통화 헬퍼
  (`FxSwapRateHelper`, `ConstNotionalCrossCurrencySwapRateHelper`, `ConstNotionalCrossCurrencyBasisSwapRateHelper`)로 만든다.
- 1년물은 스왑포인트를 쓰고 CCS·베이시스 1년물은 쓰지 않는다(겹치는 만기는 FX 스왑 우선).
- **검증** (`tests/test_curves.py`): 입력 상품을 엔진의 거래 일정·평가식으로 다시 평가해 Par 금리를 구하면 모든 만기에서
  화면 금리와 0.006bp(FX 선도 0.001원) 안에서 같다. 단 OIS는 지급 지연을 무시하므로 지급 지연이 휴일에 걸리는 날은 이를 넘을 수 있다
  (11-25 스냅샷: USD OIS 1개월 0.24bp, 9개월 0.09bp, 18개월 0.02bp, JPY OIS 12~30년 0.01bp 안팎. JPY 베이시스·FX 선도의 차이는 M20 때문이며 별개다). 1주 OIS·1주 스왑포인트·CD 91일도 같은 방식으로 재평가한다(차이 0). 예: 원화 IRS 5년 3.7375%, 달러 OIS 3년 4.6103%, KRW CCS 5년 3.27%,
  USDKRW 1년 선도 1,318.85(= 현물 1,334.00 + 포인트 −15.15).

**현물과 선도환율.**
- 현물 호가는 결제일(T+2) 기준이다. 엔진은 평가일 기준 환율로 바꿔 쓴다:
  `S_c = 호가 x DF_KRW(결제일) / DF_c(결제일)` (`MarketData.spot`, 호가는 `spot_quote`).
- 선도환율은 1단위당 원화로 `F_c(t) = S_c x DF_c(t) / DF_KRW(t)`이다. 스왑포인트로 만든 1년 이하 선도는 화면 선도(현물 + 포인트)와 같다.

**금리 변동성.**
- USD 담보 할인 커브 대표 상품 10년물의 주간 변화로 추정한다(USD SOFR OIS, KRW CCS, JPY OIS + 베이시스).
- 그래서 USD 대비 베이시스 변동이 섞여 있다. KRW CCS와 JPY OIS+베이시스가 그렇다.

**환율 간 상관.**
- USDKRW와 JPYKRW 사이는 USDJPY 내재변동성으로 역산한다(`implied_fx_corr`).
  ```
  rho = (s_USDKRW^2 + s_JPYKRW^2 - s_USDJPY^2) / (2 s_USDKRW s_JPYKRW)
  ```
- 거래 만기(10년 상한)의 term vol로 계산한 상수를 쓴다.
- 나머지 상관은 과거 추정치다.
- 두 값을 섞은 행렬이 양정치가 아니면 고유값을 1e-6 이상으로 잘라 다시 정규화한다.

**엔/원 검토 기준 스냅샷.** 2026-11-11 `market_snapshot.json`이다(`load_legacy`).
- KRW·JPY만 있고 USD 커브와 1년 미만 상품이 없다. 회귀 테스트·엔/원 검토용이다.
- 같은 QuantLib 헬퍼로 1년물(CCS, 베이시스, OIS, IRS)부터 부트스트랩한다. 1년 이내는 1년 구간 선도가 평탄하다.
- 베이시스 헬퍼의 USD 다리(SOFR 플랫, 담보 통화)는 어떤 USD 커브에서도 Par라 4% 평탄 커브를 넣는다.

## 4. 시뮬레이션 ([linefee/engine.py](../linefee/engine.py))

**위험요인.** 거래에 필요한 것만 쓴다.
- 금리: 거래 통화 + KRW
- 환율: KRW 외 통화

**금리.** 통화별 평행이동 요인 하나다.
```
x_c(t+dt) = x_c(t) e^{-kappa dt} + sigma_c sqrt((1 - e^{-2 kappa dt}) / (2 kappa)) Z    (kappa = 0이면 sigma sqrt(dt) Z)
P_c(t,T) = P_c(0,T)/P_c(0,t) x exp(-B(T-t) x_c(t) - B(T-t)^2 Var[x_c(t)] / 2)
B(tau) = (1 - e^{-kappa tau}) / kappa,  kappa = 0이면 tau
```
- 경로 평균 할인계수는 오늘의 선도 할인계수와 같다.
- `sigma_c`는 과거 추정치에 변동성 배수를 곱한 값이다. `kappa` 기본값은 0(Ho-Lee)이다.
- kappa 부호별 처리: kappa ≠ 0이면 위 OU 식을 쓰고(kappa < 0도 같은 식이 성립하며 요인이 발산하는 모형이 된다. 화면은 경고만 한다), |kappa| < 1e-12는 0으로 보아 Ho-Lee 식을 쓴다. 경로 분산·B(tau)·quanto 공분산이 모든 kappa에서 같은 분기를 탄다.

**환율.**
```
X_c(t) = F_c(t) x exp(W_c(t) - V_c(t)/2),  V_c(t) = (만기 t ATM term vol)^2 x t
```
- 10년 이후 변동성은 평탄하다.
- 1년 미만 만기는 스냅샷의 최단 만기인 1년 ATM 변동성을 평탄하게 적용한다 (`np.interp`의 양 끝 평탄). 앱은 만기 0.25년까지
  입력할 수 있으므로, 단기 FX 선도 등의 E/L·PFE는 1년 변동성에 의존한다. 단기 내재변동성 기간구조는 쓰지 않는다.

**상관.** 3장의 행렬을 촐레스키 분해해 독립 정규난수에 적용한다.

**시간 격자.** 0부터 마지막 지급 시점까지 균등 분할한다. 간격은 0.25년 이하이고 구간은 최소 24개다
(1년 FX 선도는 약 0.04년 간격).

**대조 난수(antithetic).** 정규난수 절반을 만들고 부호를 바꾼 짝을 붙인다. 경로 i와 i + n/2가 짝이다.
표준오차는 짝 평균으로 계산한다.

**quanto 드리프트.** 원화로 본 외화 현금흐름 X_c(t) P_c(t,T)의 경로 평균이 오늘 커브의 선도가치가 되도록,
외화 금리 요인에서 환율과의 공분산을 뺀다.
```
x_c(t) ← x_c(t) - Cov(W_c(t), x_c(t)),   Cov(t_n) = Cov(t_n-1) e^{-kappa dt} + rho_{r_c,fx_c} x sd_fx,n x sd_r
```
이산 격자에서 정확한 값이라 E[X_c P_c] = F_c(t) P_c(0,T)/P_c(0,t)가 성립한다(가우스 요인의 지수 기대값).

**목표 대비 근사.**
- 1요인이라 기울기 변화를 반영하지 못한다.
- 베이시스가 고정이라 할인 커브와 추정 커브가 같이 움직인다.

## 5. 경로별 가치 (`leg_value_paths`)

각 격자 시점 t에서 남은 현금흐름(지급일 ≥ t)을 경로별 할인계수로 평가한다. 지급일이 t와 같은 현금흐름은
아직 남은 것으로 본다(지급 직전 가치). 그래서 마지막 시점의 가치는 만기 결제액이고, 적분에서 마지막 구간이 빠지지 않는다.

**고정 다리.** `명목 x 금리 x 일수 비율`이고, 만기 원금이 있으면 더한다.

**변동 다리.**
```
지급액 = 명목 x [ P_proj(t,시작)/P_proj(t,지급) - 1 + 스프레드 x 일수 비율 ]
```
- 추정 커브도 같은 통화 요인으로 움직인다(베이시스 고정).
- **근사:** 이미 시작한 구간(시작 ≤ t)의 금리는 오늘의 선도로 확정됐다고 본다. 원래는 그 경로의 리셋 시점 금리를 써야 한다.

**원화 환산.** 다리 가치에 그 경로의 환율을 곱하고 방향 부호를 붙인다. 거래 가치는 두 다리의 합이다.

**t=0 가치**(`trade_value_today`)는 같은 식에 x = 0, 평가일 기준 환율을 넣은 값이다.

**선도가치**(`trade_forward_value`). 오늘 커브로 본 시점별 기대 가치다.
```
E[V(t)] ≈ sum_다리 F_c(t) x sum_{지급 >= t} 금액(오늘 선도로 추정) x D_다리(지급) / D_다리(t)
```
- 시뮬레이션의 경로 평균과 몬테카를로 오차 안에서 같다(13.6). quanto 드리프트(4장) 덕분이다.
  변동 다리 추정 커브와 할인 커브의 곱에서 생기는 볼록성 차이는 무시한다.
- 해석적 FVA(6장)에 쓴다.

## 6. 담보와 조달비용

**VM 가정.** VM CSA는 임계치 0, 최소이전금액 0, 정산 지연 0으로 본다. 그래서 담보 = 시가(C = V)이고 상대방 익스포저는 0이다.

**조달 필요액.** 헤지 방식과 무관한 하나의 식이다.
```
B(t) = sum_{무담보 상대방} V_cp(t) - G(t)
G(t) = G(0) x 남은 비율(t),   G(0) = V_고객(0) + V_헤지(0) + min(upfront, 0)
조달이익 인정(기본): FVA = s x int E[B(t)] x D(t) dt              (해석적: E[B] = 무담보 거래 선도가치 - G)
불인정:              FVA = s x int E[max(B(t), 0)] x D(t) dt       (시뮬레이션)
s = 헤지 담보 통화의 담보 조달 스프레드 (USD: FTP − SOFR 12bp, KRW: FTP − CCP KRW 담보 이자 12bp),
D = KRW 할인 커브(USD 담보),  적분 = 사다리꼴
```

**식의 뜻.**
- 스프레드가 대칭이고 조달이익을 인정하면 `s x max(B,0) - s x max(-B,0) = s x B`라 FVA가 B에 선형이다.
  그래서 경로 분포가 아니라 기대값 E[B]만 영향을 주고, 이를 오늘 커브의 선도가치로 정확히 계산한다(몬테카를로 잡음 0).
  불인정이면 부족한 경로만 비용이 되어 옵션 가치가 생기므로 시뮬레이션을 쓴다.
- 화면의 조달 필요액 E[max(B,0)], 여유 E[max(−B,0)]는 시뮬레이션 값이고 표시용이다.
- VM 상대방은 담보 = 시가이므로 대차가 상쇄되어 B에 들어가지 않는다.
- 무담보 시가는 은행이 받을 돈(미수 자산)이다. 이 중 첫날 이익으로 인식한 비현금 부분 G는 자본(CET1)으로 조달된 것으로 보고, 나머지만 차입이 필요하다. 9장의 KVA 처리와 같은 전제다.
- G(0)에 `min(upfront, 0)`을 넣는 이유: 고객에게 현금을 줬다면 그 부분은 자본이 아니라 차입으로 산 것이기 때문이다.
- 받은 upfront 현금은 자본이고, 조달을 대체하는 효과는 KVA에서만 반영한다(이중 계산 방지).

**남은 비율(t)** (`engine.remaining_value_ratio`, 오늘 커브 기준). 라인피 현금흐름의 원화 선도가치 / 오늘 가치다.
- 통화스왑·IRS: 조정 다리 쿠폰(금리 1단위분 = 일수 비율)의 남은 선도가치. 수수료가 쿠폰으로 들어오며 줄어든다.
  외화 다리면 `F_c(t) x sum_{지급 >= t} 일수 비율 x D_c(지급) / D_c(t)`로 원화 선도가치를 쓴다(원화 기준 이자 누적).
- FX 선도: 만기 KRW 금액 하나이므로 만기 전까지 `1 / DF_KRW(t)`이고 만기 뒤 0이다.
- **근사:** 경로별 수수료 가치 대신 결정적 비율을 쓴다.

**거래일 시점 확인.**

| 경우 | B(0) |
|---|---|
| BTB, 오프마켓(공공기관 A 건) | 96.4 − 17.1 = 79.3 = 딜러에 낸 VM |
| 시장가 헤지, 시장가 고객 거래 | 0 |
| 시장가 헤지, 오프마켓 고객 거래, 고객에게 X 지급 | X |

**이전 버전과의 관계.** 이전 버전은 `B = 딜러에 낸 VM`이었고, 이는 BTB일 때만 맞았다. 엔/원 공공기관 A 건의 FVA는 3.34억원이다(13.1).

**IM.**
- 받은 IM은 분리 보관되므로 조달 이익이 없고, SA-CCR NICA에만 쓴다.
- 낸 IM 비용은 `MVA = int IM(t) x IM 조달 스프레드 x D dt`다. 기본 스프레드가 0이므로 기본값에서는 MVA = 0이다.

## 7. 규제자본 ([linefee/regcap.py](../linefee/regcap.py))

### 7.1 SA-CCR (경로별)

통화스왑과 FX 선도는 환율 자산군 하나로만 분류한다. 금리 다리는 제외한다(확정 사항).

```
조정명목(t) = 외화 다리 명목 x 그 경로의 환율 X_c(t)     (두 다리 모두 외화면 큰 쪽)
AddOn(t)    = 4% x 조정명목(t) x MF
무담보: MF = sqrt(min(max(잔존만기, 10/250), 1)),     RC = max(V, 0),  초과담보 = V
VM:     MF = 1.5 x sqrt(MPOR / 250),     RC = 0 (C = V, 임계치 0),  초과담보 = -NICA
        NICA = 받은 IM x (1 - 담보차감률 4%)   (VM+IM일 때)
승수 = min(1, 0.05 + 0.95 x exp(초과담보 / (2 x 0.95 x AddOn)))
EAD(t) = 1.4 x (RC + 승수 x AddOn)   (경로별. 필요자본·KVA를 경로별로 구한 뒤 평균하고 표준오차를 낸다)
잔존만기 = 마지막 지급 시점 - t
```
- **10영업일 하한.** 무담보 MF의 만기 M은 하한 10영업일(10/250년, 267.카.(1)), 금리 자산군 감독 듀레이션의 종료일 E도 하한 10영업일(267.자.(1))이다. 마지막 지급 시점 노드(잔존 0)에는 하한을 적용하지 않는다(add-on 0, RC만 남김). 기본 시간 격자는 간격이 min(0.25년, 만기/24)라, 만기가 약 0.96년 미만인 거래는 마지막 노드 직전 잔존만기가 10/250년보다 짧아 하한이 걸린다(예: 5,000경로에서 0.25년 FX 선도 순마진 −0.0013억, 0.5년 −0.0007억). 만기 약 0.96년 이상이면 기본 격자에서 하한이 걸리는 노드가 없다.
- 담보 상계 집합의 EAD를 무담보 EAD로 제한하는 상한은 적용하지 않는다.

### 7.2 필요자본

```
신용:  필요자본 = EAD x 신용 RW x CET1 목표비율
CVA:   K = DS(0.65) x RW_cva / alpha(1.4) x M x DF(M) x EAD x 한계계수
       M = max(잔존만기, 10영업일)(상한 없음),  DF(M) = (1 - e^{-0.05 M}) / (0.05 M)
       필요자본 = K x 12.5 x CET1 목표비율
```
- **M의 하한과 상한.** 상한 5년은 313.(3)이 126.가의 5년 상한을 적용하지 않도록 해 없다. 하한은 10영업일(10/250년)이다: 126.다가 상계계약 하의 장외파생상품에는 하한을 최소보유기간(71.나.(1), 장외파생 10영업일)으로 정하므로 126.가의 1년 하한은 쓰지 않는다. 마지막 지급 시점 노드(잔존 0)는 M = 0으로 두어 RC만 남긴다. 하한이 실제로 걸리는 경우는 7.1과 같다(만기 약 0.96년 미만 거래).
- **근사:** 은행 CVA 포트폴리오 대비 증분은 한계계수로 근사한다.
  - 정확한 값은 `K(P ∪ T) - K(P)`이고, 계산하려면 은행 전체 SCVA가 필요하다.
  - 한계계수의 기본값 0.5는 거래상대방이 충분히 분산된 경우의 ρ다.
  - 수식은 `dK/dSCVA_c = DS (ρ² ΣSCVA + (1-ρ²) SCVA_c) / K_축약`이다.

### 7.3 신용 RW (DECISIONS M16, M16a, M17)

상대방마다 둘 중 하나를 쓴다. 마스터의 `rw_method` 열이 고른다.

- **고정 RW.** 금융기관(외부등급, 별표3 35·37조), 공공기관(32조 구분별 0/20/50%), 헤지 딜러(20%), CCP(2%).
- **기본내부등급법 (기업).** [linefee/regcap.py](../linefee/regcap.py)의 `irb_rw`. 별표3 120조 산식이다.

```
PD' = max(PD, 0.05%)                                   (123)
R   = 0.12 w + 0.24 (1 - w),  w = (1 - e^{-50 PD'}) / (1 - e^{-50})
      중소기업(매출 700억 이하): R - 0.04 (1 - (S - 7) / 63),  S = 매출(10억원 단위, 7 미만은 7)   (120.나)
b   = (0.11852 - 0.05478 ln PD')^2
K   = [LGD N((G(PD') + √R G(0.999)) / √(1 - R)) - PD' LGD] x (1 + (M - 2.5) b) / (1 - 1.5 b)
RW  = 12.5 K   (1.06 승수 없음),  LGD = 40% (124.나 감독 LGD),  PD 100%(부도)는 RW 0
M(t) = min(max(잔존만기, 10영업일), 5년)                (126.가 상한, 126.다 하한)
```

- RW는 시점마다 M(t)으로 다시 계산한다(잔존만기가 줄면 RW도 준다). PD는 은행 PD 마스터의 감사 구분 열(외감·비외감·LDP·일반기업)에서 가져오고, E/L에도 같은 PD를 쓴다(E/L·CVA 가격용 LGD는 60%).
- 검증: `tests/test_irb.py` (바젤 예시 PD 1%, LGD 45%, M 2.5 → 92.32%).
- 근사: 중소기업 판정은 기업집단 매출 대신 개별 매출(고객 파일)로 한다.

## 8. IM (SIMM 단독)

- ISDA SIMM v2.8+2512 RatesFX delta만 쓴다. 계산통화는 USD다.
- 파라미터는 기존 [simm.py](../simm.py)를 그대로 쓴다.
- **위험요인.**
  - 금리 delta: 통화별 vertex PV01, 해당 통화 할인 커브 zero +1bp 기준.
  - 통화간 베이시스: USD 외 통화에만 둔다. 민감도는 그 통화 PV01 합계다.
  - FX delta: USD 외 통화, 1% 변화.
- **위험계수 구분.** KRW·USD는 regular, JPY는 low volatility다.
- **집계.**
  ```
  IR^2 = sum K_b^2 + gamma x sum_{b≠c} S_b S_c
  FX^2 = sum ws^2 + rho_fx x sum_{i≠j} ws_i ws_j
  IM   = sqrt(IR^2 + FX^2 + 2 psi IR FX)
  ```
  집중도 계수는 1이다.
- **원금 교환은 IM 대상이 아니므로 뺀다.**
  - FX 선도는 IM이 0이다.
  - 변동 다리는 다음 지급일에 `(명목 + 확정 쿠폰)`, 만기에 `-명목`, 스프레드는 각 지급일에 두는 현금흐름으로 바꿔 계산한다.
- **미래 IM.** 오늘 커브의 선도와 선도환율로 남은 현금흐름을 평가한다.
  - 경로별로 다시 계산하지 않고 연 단위로 구한 뒤 선형 보간한다.
- **IM 교환.** 양방향 같은 금액으로 보고, 임계치(5천만유로)는 적용하지 않는다.

## 9. 비용, 첫날 이익, 순마진 ([linefee/pricing.py](../linefee/pricing.py))

```
E/L (무담보 상대방) = LGD x int EE(t) x D(t) x (-dS(t)),  S(t) = (1 - PD)^t,  EE = E[max(V,0)]
KVA (항목별)        = int (h - r(t)) x E[K(t)] x e^{-h t} dt
                     h = 세후 요구수익률 / (1 - 세율)
                     r(t) = 원화 IRS(CD) 커브의 구간 선도금리 + alpha (KVA 조달 스프레드, 기본 10bp)
                            (확정. 비교용으로 원화 CCS(USD 담보) 커브를 고를 수 있다)
적분은 모두 사다리꼴이다. 구간 [t_i, t_i+1]의 값을 양 끝 노드에 반씩 나눈다.
첫날 이익           = V_고객(0) + V_헤지(0) + upfront
회계 손익           = 첫날 이익 - E/L                    (내부 위험조정영업수익 기준)
조달비용 반영 손익  = 회계 손익 - FVA - MVA               (이후 기간 손익으로 실제 발생, 현재가치)
자본비용 반영 손익  = 조달비용 반영 손익 - KVA = 순마진   (손익분기 수수료·요구수익률의 기준)
```

**세 단계로 나누는 이유.**
- 내부 성과평가는 E/L만 차감한다. FVA는 FTP를 통해 매년 실제 비용으로 잡힌다.
- KVA는 성과평가에 잡히지 않는 자본비용이다.
- 화면의 손익분기 수수료와 손익분기 요구수익률은 모두 자본비용 반영 손익 = 0 기준이다.

**KVA 정의.** 첫날 이익을 CET1로 적립하고, 묶인 자본이 조달을 대체한다(확정 방식).
- 주주 현금흐름을 h로 할인한 NPV와 같다.
- r(t)는 자본이 대체하는 은행의 무담보 KRW 조달 금리다. 기준 커브는 원화 IRS(CD) 커브다(2026-11-12 확정).
  USD 담보 KRW 커브(CCS)는 조달금리가 아니며 온쇼어 베이시스만큼 낮다(2026-11-12 기준 5년 약 47bp).
  엔/원 공공기관 A 건에서 두 선택의 차이는 13.1에 있다.
- 담보 상대방의 E/L은 0이다(정산 지연 0).

**연 bp 환산.** 원화 금액을 손익분기 조정 다리의 연금계수로 나눈다. 연금계수는 금리 1당 원화 현재가치다.
```
bp = 금액 / (명목 x sum 일수 비율 x DF_c(지급일) x S_c) x 1e4
```

**몬테카를로 표준오차.** 순마진 = 첫날 이익 − 비용이고, 비용은 모두 경로별 기여의 평균이다(E/L, 해석적 FVA는 상수,
경로별 필요자본의 KVA, MVA는 상수). 경로별 순마진(대조 난수면 짝 평균)의 표준편차 / sqrt(개수)를 표준오차로 보여준다.

## 10. 손익분기

**손익분기 라인피(running·마진).**
- 조정 다리를 정한다.
  - 고객 다리(모든 구조): 고객 수취 다리
  - 헤지 다리(BTB): 헤지 지급 다리
  - 직접 입력: 사용자가 둘 중 하나를 선택
- 그 다리 금리를 δ만큼 은행에 유리하게 바꿔 순마진 = 0이 되는 δ를 찾는다. FX 선도는 선도환율(원/외화 1단위)을 바꾼다.
- 조정 단위 1의 원화 현재가치(`fee_unit_pv`)는 통화스왑은 다리 연금, FX 선도는 `외화 명목 x DF_KRW(만기)`다.
- 조정이 익스포저를 바꾸므로 같은 난수(seed)로 다시 시뮬레이션한다.
- 찾는 순서:
  1. 첫 추정은 `δ1 = -순마진 / 조정 단위 현재가치`다.
  2. 이후는 할선법이다.
  3. 순마진 절댓값이 100만원 이하가 되거나 할선을 6번 하면 멈춘다(전체 계산은 최대 8번).
  4. 마지막 순마진이 100만원을 넘으면 화면이 "수렴하지 않음"을 경고한다.
- 음수가 나오면 그만큼 여유가 있다는 뜻이다.
- 화면의 손익분기 라인피는 `제안 라인피 + δ`다.
- 표준오차는 마지막 계산의 순마진 표준오차 / 조정 단위 현재가치다.

**손익분기 upfront (BTB).**
- upfront는 익스포저를 바꾸지 않으므로 지금 조건의 부족분(`-순마진`)이 그대로 답이다.
- running 라인피를 넣은 BTB에서는 "upfront로만 받는다면"을 함께 보여준다. running 라인피가 없는 같은 BTB 구조를 한 번 더 계산한 `-순마진`이다.
- upfront 방식에서는 "running으로 받는다면"을 함께 보여준다. upfront 0, 고객 다리 라인피 0에서 시작해 손익분기를 따로 푼 값이다.

**손익분기 세후 요구수익률.**
- KVA 외 비용은 요구수익률과 무관하므로 그대로 두고, KVA만 다시 계산한다.
- `KVA(h) = Σ (h − r) K e^{−ht}`는 h에 단조가 아니다. h가 아주 크면 e^{−ht} 때문에 다시 작아진다.
- 그래서 0%부터 0.1%p씩 올리며 처음 순마진 < 0이 되는 구간을 찾고, 그 안에서 이분법을 쓴다.
- 0%에서 이미 손실이면 "0% 미만"으로 표시한다.
- 50%까지 계속 이익이면 "50% 이상"으로 표시한다. 이 KVA 정의에서 모든 수준에서 이익이라는 뜻이다.
  이때 화면은 0~50% 구간의 최저 순마진과 그 요구수익률도 함께 보여준다(`Run.worst_net`). 이익 폭이 얇은지 판단하는 용도다.

## 14. 원화 IRS·달러 OIS (CCP·BTB·딜러 라인 헤지)

**거래.**
- 같은 통화 두 다리(고정 vs 변동)이고 원금 교환은 없다. 관행은 화면에서 고정한다.

| 상품 | 변동금리 | 지급 | 일수 | 평가 커브 (할인 = 추정) |
|---|---|---|---|---|
| 원화 IRS | CD 91일 | 분기, T+1 | ACT/365F | KRW CD (CD 91일 + `KWSWO`) |
| 달러 OIS | SOFR 후취 복리 | 연 1회, T+2 | ACT/360 | USD SOFR (`USOSFR`) |

- 다리에 `discount = "local"`을 두어 USD 담보 커브 대신 자국 통화 담보 커브로 평가한다(`MarketData.disc_for`).
  CCP VM이 거래 통화 현금이기 때문이다.
- **근사:** KRW는 KRW IRS(CD) 커브를 할인에도 쓴다. KOFR OIS 할인과의 차이는 무시한다.
- 변동 다리는 `P(t,시작)/P(t,지급) − 1`로 평가한다. SOFR 후취 복리도 단일 커브에서는 이 식과 같다.
- "시장 파 금리로 채우기"는 같은 조건의 Par 헤지를 풀어 고정금리를 구한다. 만기나 스프레드를 바꾸면 자동으로 다시 채운다.
  커브가 화면 상품을 그대로 재현하므로 파 금리는 화면 금리와 같다(5년 3.7375%).

**시뮬레이션.**
- 해당 통화 금리 요인 하나를 쓴다. 달러 OIS는 원화 환산을 위해 USDKRW 요인도 함께 쓴다.
- 원화 IRS의 KRW 금리 변동성은 KRW IRS 10년물 주간 변화로 추정한다(`r_KRW_irs`, 2026-11-12 기준 연 88bp).
  통화스왑에 쓰는 KRW CCS 기준 97bp와 다르다.

**헤지 상대 선택** (화면 "헤지 상대", `IRS_HEDGES`).
- **CCP:** 청산 Par 거래. 아래 표의 처리를 쓴다. 라인피는 고객 다리 running만 있다.
- **딜러 라인 (Par):** 딜러와 양자 Par 거래. 미러 거래의 고정금리를 조정해 거래일 가치 0으로 만들고(`pricing.market_hedge`), 라인피는 고객 다리 running만 있다.
- **BTB (딜러):** 고객 거래와 같은 조건(라인피 제외)의 딜러 양자 거래(비표준 일정·오프마켓 등 청산 불가 거래). 넘어온 오프마켓만큼 거래일에 VM을 낸다.
  라인피 위치는 고객 다리 running, 헤지 다리 running, upfront 중 고른다.
- **양자 헤지(BTB·딜러 라인)의 처리:** 딜러 마스터의 CSA를 따른다. 딜러 SIMM IM(MVA), 딜러 VM 담보 통화 기준 FVA 스프레드,
  딜러 신용 위험(CVA·자본)을 쓴다. 다리의 할인은 CCP와 같이 자국 통화 담보 커브(`discount = "local"`)이고 VM 담보 통화는 할인 커브를 바꾸지 않는다(6장).
  양자 헤지의 파 금리는 할인 커브를 바꿔도 같다(0.0005bp 미만).

**CCP 헤지** (`pricing.market_hedge`).
- 미러 거래의 고정금리를 조정해 거래일 가치를 0으로 만든다.

| 항목 | 처리 |
|---|---|
| VM | 거래 통화 현금 일일 정산, 정산 지연 0 |
| 조달 스프레드 | 담보 통화 기준: 원화 IRS는 KRW 담보 조달 스프레드(FTP − CCP KRW 담보 이자, 화면 입력, 임시 12bp, 확인 필요), 달러 OIS는 USD 12bp. KVA 조달 스프레드와 별개 |
| IM | 은행이 CCP에 일방 납부, 받는 IM 없음 |
| IM 금액 | `z(99%) x sigma x sqrt(5/250) x |두 다리 순 PV01|`, 반기 격자로 aging 후 보간 (`regcap.ccp_im_profile`). 변동 다리는 다음 리셋일에 명목 + 확정 쿠폰, 만기에 −명목으로 바꿔 PV01을 잰다. 실제 CCP 모형(과거 시나리오 VaR)의 근사 |
| MVA | 낸 IM x IM 조달 스프레드 (기본 0) |
| 신용 자본 | 적격 CCP 거래 익스포저 RW 2%. SA-CCR 담보 상계 집합, MPOR 10영업일(별표3 296.사, `CCP_REG_MPOR_DAYS`). CCP IM의 5영업일 VaR(위 IM 금액)과는 별개 |
| CVA 자본 | 없음 (적격 CCP 거래 면제, 별표3 306) |
| 미반영 | 부도기금 출연 자본, 낸 IM에 대한 RW (분리 보관 가정) |

**SA-CCR 금리 add-on** (`regcap.addon_before_mf`).
```
AddOn = 0.5% x 명목(원화, 그 경로의 환율) x SD x MF,  SD = (1 - e^{-0.05 E}) / 0.05,  E = 잔존만기
```
- 감독 델타의 절댓값은 1이다. 거래 1건이라 헤징셋과 만기 버킷 간 상계가 없다.

**고객 쪽.** 통화스왑과 같다. 무담보 SA-CCR, 신용 RW, BA-CVA, E/L을 쓴다.

**FX 선도 기본값.** 상품을 FX 선도로 바꾸면 헤지가 딜러 라인으로 바뀐다(`on_product_change`).
