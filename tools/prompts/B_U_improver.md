# B U: 화면 개선 (sonnet, 라운드 R1·R2)

먼저 `tools/prompts/B_COMMON.md`를 읽는다. 역할은 ui다. `app.py`, `ui/**`, `.streamlit/secrets.toml.example`, `tests/test_app.py`, `requirements.txt`, `README.md`만 고친다.

지시에 라운드(`R1` 또는 `R2`)와 직전 실행 이름(예 `r0`)이 들어 있다. 아래에서 `<이전>`은 그 실행 이름이다.

## 목표

본부 세일즈가 거래를 넣고 결과를 읽을 때 **틀리지 않게** 하는 것이다. 채점은 스크립트가 한다:

- 주지표: 공개 과제 성공 수(답이 정답과 일치), 놓친 오입력 수(틀린 입력으로 계산한 결과를 답으로 냄).
- 함께 보는 것: 오래된 결과 사용, 해석 오류(입력은 맞는데 다른 숫자를 읽음), 입력 확인 가능(결과 옆 입력 요약), 조작 수, 혼란 보고, 오입력 주입 포착률과 오경고율.
- 채택 조건: 주지표 개선 + 숨긴 과제(당신이 볼 수 없는 과제)에서 나빠지지 않음 + 가드(값 불변, 일반 화면에 관리자 영역 없음, 오래된 결과 미표시 0, 오경고율이 높아지지 않음).
  공개 과제에만 맞춘 수정은 숨긴 과제에서 걸러진다. **과제가 아니라 실수의 종류를 고친다.**

## 읽을 것 (이것만)

1. `ui_eval/runs/<이전>/feedback_public.md` — 과제별로 무엇이 틀렸는지, 혼란 보고 원문.
2. `ui_eval/runs/<이전>/score.json`, `faults.json` — 지표와 오입력 주입 결과.
3. 필요하면 공개 세션의 행동 로그 `ui_eval/runs/<이전>/p1|p2/<과제>/log.jsonl` — 어떤 순서로 무엇을 눌렀는지.
4. `ui_eval/tasks_public.yaml` — 과제 지시문과 유형.
5. R2라면 `ui_eval/runs/r1/verdict.json` — R1이 채택됐는지, 아니면 왜 되돌려졌는지. 되돌려졌다면 지금 화면은 R1 이전 상태다.

`c:\projects\fun_private\`는 열지 않는다. 숨긴 과제의 문항·로그·정답을 다른 경로로 알아내려 하지 않는다.

## 일하는 순서

1. 실패를 원인별로 묶는다. 예: 단위를 몰랐다 / 방향을 고객 기준으로 골랐다 / 조건을 바꾸고 다시 계산하지 않았다 / 시장가로 다시 맞추지 않았다 / 결과에서 다른 숫자를 읽었다 / 경고를 이해하지 못했다.
   각 묶음에 근거(과제 id, 페르소나, 로그의 행동 번호, 혼란 보고 문장)를 붙인다. 근거가 세션 1건뿐인 것은 뒤로 미룬다.
2. 묶음마다 화면에서 무엇이 그 실수를 허용했는지 적고, 고칠 방법을 정한다. 한 라운드에 3~5개 묶음까지. 효과가 클 것부터.
3. 고친다. 묶음 하나에 커밋 하나.
4. 드라이버로 직접 확인한다: `python -m ui_eval.driver start dev p1 <과제>` 로 실패했던 과제 2~3개를 모델의 눈으로 다시 풀어 본다
   (드라이버가 찍는 글이 페르소나가 보는 전부다. 색·위치·굵기는 전달되지 않는다. **글로 읽히는 개선**이어야 한다).
5. 확인 명령을 돌린다.

## 고치는 방향 (예시일 뿐, 근거가 있는 것만 한다)

- 입력한 값을 사람이 읽는 말로 되돌려 보여 주기 (예: 명목 칸 옆에 "= 2억 달러", 방향을 고객 기준 문장으로 "고객이 고정금리를 받는다").
- 계산 결과 맨 위에 입력 요약(계약 10번): 무엇을 계산했는지 한눈에. 결과가 어떤 입력의 것인지 분명히.
- 계산 뒤 입력이 바뀌면 결과를 흐리게 두지 말고 숨기거나, 결과 숫자보다 먼저 읽히는 경고를 둔다(계약 8번의 글자는 유지).
- 이상한 크기의 값(명목, 금리, 라인피)에 경고. 단, 정상 입력에 뜨면 오경고로 감점된다. 문턱은 넉넉히.
- 세일즈가 쓰지 않는 것(용어, 표, 설정)을 접거나 뒤로 보내고, 묻는 숫자(자본비용 반영 손익, 손익분기 라인피, 충분한지)를 결과 맨 위에 평이한 말로.
- 경고 문장은 "무엇이 이상한지 + 어떻게 하면 되는지"를 한 문장씩.

## 지킬 것

- B_COMMON.md "화면 계약" 전부. 특히 key와 단위(3번), `result` 항목(2번), 관리자 영역(5번).
- 엔진 결과를 바꾸지 않는다. 화면이 엔진에 넘기는 값이 같은 입력에서 달라지면 안 된다 (`python tools/golden_check.py --ui`).
- 일반 사용자 화면에 관리자 영역을 다시 내놓지 않는다.
- 과제 지시문의 문구, 과제 id, 정답 숫자에 맞춘 분기를 넣지 않는다 (예: 특정 명목일 때만 뜨는 안내).
- 화면 프레임워크 교체는 R1에서만, B_COMMON.md의 조건을 만족할 때만. 교체하려면 먼저 근거를 최종 보고 형식으로 정리하고, `ui/testing.py`까지 한 번에 낸다. 반쯤 옮긴 상태로 끝내지 않는다. 확신이 없으면 Streamlit 안에서 고친다.
- 하니스(`ui_eval/`)가 불편하거나 틀렸다고 보이면 고치지 말고 최종 보고에 적는다.

