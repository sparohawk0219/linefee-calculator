# R1 — 방법론·규제 + 문서↔코드 정합 리뷰어

- 모델: **opus**
- 출력: `reviews/findings_R1.jsonl` (이 파일 하나만 쓴다. id는 `R1-001`부터)
- 먼저 `tools/prompts/A1_COMMON.md`를 읽고 그 규칙을 따른다.

## 맡은 질문

"이 계산기가 내는 숫자는, 문서에 쓴 방법론과 감독규정대로 계산된 것인가?"

## 볼 것

1. **규정 대조** — `linefee/regcap.py`의 SA-CCR(RC, PFE, 승수, MF, 감독 델타, 자산군 add-on), BA-CVA 축약형,
   신용 RWA, CCP 익스포저를 `reg/byeolpyo3.txt`(시행세칙 별표3) 조항과 대조한다. 상수(감독승수, 상관계수, 위험가중치 표
   `trade.BA_CVA_RW`, alpha 1.4, DS 0.65, MPOR)와 산식의 형태를 조항 번호와 함께 확인한다.
2. **SIMM** — `regcap.py`의 IM 계산과 루트 `simm.py`를 문서에 적힌 SIMM 버전 기준으로 확인한다
   (위험가중치, 상관, 집중 임계치 처리, 통화 분류).
3. **XVA 정의** — `linefee/pricing.py`의 E/L, FVA(조달 필요액·여유, FBA 인정), MVA, KVA(`retained_net`, r(t), 할인),
   첫날 이익, 순마진, 손익분기가 `docs/METHODOLOGY_v1.md`의 산식과 같은지. 부호, 할인, 적분 구간, 세전·세후 변환, 이중 계산 여부.
4. **확정 결정의 구현** — `docs/DECISIONS.md` M1~M9 각각이 코드에서 실제로 그렇게 동작하는지 항목별로 확인한다
   (기본값, 분기, 화면에서 바꿀 수 있는 범위).
5. **문서↔코드 정합** — `METHODOLOGY_v1.md`, `DESIGN.md`의 서술·표·수치 예시가 현재 코드와 맞는지.
   문서에 실린 결과 수치(예: 검증 절의 표)는 가능한 것만 다시 계산해 대조한다. 스냅샷 날짜가 달라 재현할 수 없는 수치는
   "재현 불가(스냅샷 다름)"로 구분하고 발견사항으로 내지 않는다.
6. **구버전 파일** — 루트 `xva_model.py`, `assumptions.py`, `main.py`가 `linefee/`와 다른 방법을 쓰는 곳 중,
   공개 저장소 독자가 현재 방법으로 오해할 만한 것 (`tests/regression_jpykrw.py`가 이 파일들을 쓴다).
7. **화면의 설명** — `app.py`의 라벨·도움말·캡션이 방법론과 다르게 말하는 곳.

수치·구현 버그 탐색(난수, 수렴, 경계 조건, 테스트 품질)은 R2가 맡는다. 보다가 발견하면 내되 깊이 파지 않는다.
